# 批量导入历史与报告

管理后台“书籍导入”的网页批量上传会为每一次选择文件创建一条独立报告。报告长期保留，不会被下一次上传覆盖。

- 报告显示每个文件的最终结果：新增、重复或失败。
- 重复以文件 SHA-256 判断；重复文件不会新增书籍，也不会保留第二份托管副本。报告会显示“重复，未导入”。
- 失败项会保存文件名和服务端返回的失败原因，例如格式不支持、文件过大、元数据提取或 Kindle 转换失败。
- 报告可以翻页查看；“删除记录”只删除该次报告和明细，**不会删除任何已入库书籍或原始电子书**。
- 收件箱、监控目录和 Calibre 的后台任务仍保留在原有的任务审计中；本报告页当前管理的是网页批量上传。

## 验收步骤

1. 在“管理后台 → 书籍导入”选择包含一个新 EPUB、同一 EPUB 的副本，以及一个损坏或不支持文件的批次。
2. 等待报告完成，确认摘要分别统计新增、重复和失败。
3. 打开报告明细，确认每个文件名可见，重复项显示“未导入”，失败项有原因。
4. 刷新页面并再次导入另一批，确认第一批仍能从历史中查看。
5. 删除第一批报告，确认该报告消失而其新增书籍仍可在“书目与分类”打开和阅读。

## PDF/EPUB 导入兼容性加固（2026-08-07）

- PDF Info、EPUB OPF、Calibre 覆盖字段和导入文件名在写入 PostgreSQL 前统一移除 `NUL` 字节，并把非法 UTF-8 替换为有效字符，避免 `SQLSTATE 22021` 导致整本书导入失败。
- EPUB 改用 ZIP 中的 `META-INF/container.xml` 识别，不再要求 ZIP 头必须位于文件第一个字节，也兼容缺失或被压缩的 `mimetype` 条目；普通 ZIP 仍会拒绝。
- 网页上传和历史报告对不支持格式显示中文原因，并明确 EPUB 所需的容器结构。
- 自动化回归覆盖带 `NUL`/非法 UTF-8 的 PDF 元数据、带前置字节的 EPUB、缺少 `mimetype` 的 EPUB，以及伪装成 EPUB 的普通 ZIP。

验证结果：`go test ./...` 通过；`docker compose up -d --build` 构建通过，应用与数据库健康检查均为 healthy。真实问题文件仍需在本地管理后台重试，文件本身不进入代码仓库或测试夹具。
